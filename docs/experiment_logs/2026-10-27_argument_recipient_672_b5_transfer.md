# 672条件 B5 probeの正準→実走行 転移評価（2026-10-27）

[RDR-2026-10-27-03](../decisions/2026-10-27_argument_recipient_672_actual_audit_waiver_and_transfer_metrics.md)が結果閲覧前に固定した指標どおりの評価。固定probe（B5、層8 / C=1.0、`argrec672-v1-an-003-B1_to_B5`）を再fitせずに、実走行112件（`argrec672-v1-act-003`）の`Tend_assistant`残差と、同じ条件の正準取得（`argrec672-v1-003`）の残差を比べた。出力は`artifacts/processed/argrec672-v1-tr-003-B5/`（不変、commit対象外）、[小さい要約](../../results/2026-10-27_phase2_argument_recipient_672_b5_transfer_v1.json)。実行commitは`840cb80`（クリーン）。実装は`argument_recipient_672_transfer.py`で、凍結計画の読込みに`require_matching_head=False`（既定は従来どおり真）を追加した。解析のみで、bundleのchecksum・凍結ファイルの照合は省かない。

**これは一貫性の確認であり、probeの妥当性の確認ではない。** B5の主指標はG/H `role_swap_auc` 0.613で基準0.80に届いていない。

- prefixのtoken ID列が正準と一致した106条件では、残差が**ビット単位で一致**（最大相対L2差 0、決定値差 0）した。決定論的デコードと同一prefixなので期待どおりで、取得経路の差による数値雑音は観測されなかった。
- prefixが一致しない6条件はすべて`later_tool_to_assistant`境界（D2の二資料タスク）で、train 4・validation 2。原因は後述の読取呼び出しの形の違い（6件すべてで確認済み）。相対L2差は約0.095〜0.10、コサイン0.995程度。この6条件で決定値の差が大きく（中央値2.30、最大10.24）、argmax一致は3/6にとどまる。
- **ずれの原因（6件すべてを`messages.json`・`generations.json`・prefixのtoken列で確認）**：正準履歴は`read_file`を1回ずつ別の発話で呼び（読取1→結果1→読取2→結果2）、実走行のモデルは2つの`read_file`を**1回の発話にまとめて**呼んだ（読取1・読取2→結果1・結果2）。文書内容と口座は同一で、会話の構造だけが違う。token列は6件とも実走行が正準より8トークン短く、最初の食い違いは1589〜1597番目（検証の2件は1592番目）。6件ともユーザータスク成功（strict）で、誤送金はない。D2標本8条件のうち6件がまとめ呼び、2件が正準と同じ逐次呼びだった。
- 境界別では、`user_to_assistant`（64）と`first_tool_to_assistant`（40）は全件prefix一致・決定値差0。`later_tool_to_assistant`（8）は一致2/8、argmax一致5/8。
- 検証G/Hの16条件は全件prefix一致で、正準と実走行のスコアが同一。記述的AUROCは0.670（B5の主指標0.613は48条件の別集計で、直接比較しない）。
- 訓練split 80件の記述的AUROC 1.000/0.999は学習内の値であり、妥当性の根拠にしない。

## 解釈の限定

- 転移が成立したと言えるのは「同一prefixでは同一残差が得られ、probeスコアも同一」という入力レベルの一貫性に限る。実走行で正準と異なる履歴になった場合（本標本では6/112、D2の後段境界に集中）には、スコアが大きく変わる。
- 記述的`role_swap_auc`は12/12の均衡を満たさない部分集合に対する値で、閾値判定・検定・信頼区間を作っていない。
- probe自体の読み出し能力（B5で0.613）が低いことは、この評価では変わらない。「実走行で受取人が採用されたか」はprobeスコアの一致からは言えない（AGENTS.mdの測定区別に従う）。
- ラベルの出所は条件由来の`argument_present`のまま。実走行の生成callやuser-task成功からは作り直していない。
