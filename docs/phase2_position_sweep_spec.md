## 1. 目的

手順1は`Tend_assistant`の1点だけを見て、「送金先は先に提示された口座か」（`recipient_first`）が
層24で読めることを示した（R1）。ただし、それがいつ作られたかは分からない。本仕様では、同じラベルを
次の各時点で測り、RDRの競合仮説のどれに近いかを記述する。

- **H1 読解時の束縛：** 口座を読んだ時点（口座スパン上）で、すでに読める。
- **H2 生成前のポインタ：** 口座スパンでは読めず、`Tend_assistant`で初めて読める。
- **H3 生成時の決定：** 送金呼び出しを書き始めて、口座が分岐する直前で初めて読める。

**読めることは、選択をしたことを示さない。** 本仕様の結果はすべて観察であり、因果を示すには介入が必要である（手順4）。

## 2. データ

- **対象：** `argrec672-v1-003`の訓練側正準キャプチャのうち、二口座の役割入替え条件
  （`rx_ref_y`、`ry_ref_x`）240条件・120対。手順1の主ラベルの対象と同じである。
- 検証条件（G/H/I/J）は読み込まず、`validation_rows_loaded: 0`を記録する。G/H・I/Jはすでに閲覧済みで、
  未閲覧の題材系列もないため、本仕様には独立検証の部分がない。
- 実走行の結果とモデルの生成callは、ラベルにも位置の決定にも使わない。
- **入力：** 各条件の正準bundleにある`prefix.json`（token ID列・offset・テキスト。checksumを照合する）。
  これに固定の送金呼び出しの書き出しを連結し、1回だけ順伝播する。生成は行わない。

## 3. 測定位置

すべて同じ順伝播の中の位置である。token indexとtoken IDを各条件で保存する。

| ID | 位置 | 定義 | 主に関わる仮説 | 判定 |
|---|---|---|---|---|
| `A1` | 先に提示された口座の末尾 | 提示テキスト（手順1と同じ定義）で先に現れる口座の文字範囲と重なる最後のtoken | H1 | 判定する |
| `A2` | 後に提示された口座の末尾 | 後に現れる口座の文字範囲と重なる最後のtoken | H1 | 判定する |
| `T` | `Tend_assistant` | 正準prefixの最後のtoken（手順1と同じ位置） | H2 | 判定する |
| `S` | 書き出しの末尾 | 書き出し`<tool_call>\n{"name": "send_money", "arguments": {"recipient": "`の最後のtoken（次は`GB`） | H3 | 判定する |
| `G` | `GB` | 書き出しの後に`GB`を連結した最後のtoken（次は口座ごとに異なる数字） | H3 | 判定する |
| `D` | 分岐した数字 | `G`の後に、**送金先口座の**最初の数字を連結した位置 | — | 報告のみ |

- **位置は役割ではなく提示順で決める。** 「送金先口座のスパン」で位置を決めると、ラベルによって見る位置が変わり、
  位置そのものからラベルが漏れるためである。対内では`A1`・`A2`の文字列と位置が揃い、役割文だけが入れ替わる。
- **`A1`は、因果的な注意のため、それより後の文を見ていない。** 先の口座の役割を示す文が口座の後にある場合、
  `A1`ではその情報を原理的に読めない。これは結果の解釈で考慮する（8節）。
- **`D`はラベルが入力に含まれている**（送金先の数字を与えている）。そのため、読めて当然の位置である。
  スロット付近の手順が働いているかを確かめる陽性対照としてだけ報告し、判定には使わない。
- **口座の分岐点（2026-11-12、トークナイザーのみで確認）：** 書き出しの直後、4候補は`GB`・数字1文字の順に
  分割され、最初の数字（8・4・6・1）で互いに分岐する。このため`G`が分岐前の最後の位置である。
  RDRの「`GB`」と「最初の分岐トークン」は、この位置にまとまる。本番のトークン化でも同じかを、事前確認で全条件について照合する。

## 4. ラベルと対照

- **主ラベル：** 手順1と同じ`recipient_first`。
- **陽性対照：** `source_role`（user / tool）を各位置で読む。履歴構造から自明に決まる情報なので、手順の健全性確認にだけ使う。
- **特異性対照：** 手順1と同じ`account_block_position`（Uタスクのみ）を各位置で読む。
- **ランダムラベル：** 手順1と同じく、系列単位でラベルを反転する。
- **表層ベースライン：** 手順1と同じTF-IDF・長さ・口座identityに、**位置ベースライン**を加える。入力は正準prefixである。
  位置ベースラインは、`A1`・`A2`のtoken indexとprefixのtoken数の3値だけを特徴にしたロジスティック回帰である（2026-11-12追加、下の注を参照）。
  `S`・`G`・`D`で連結する書き出しは全条件で共通なので、表層ベースラインは変わらない。
  - 注：2026-11-12の確定後、モデルを使わない確認で、120対中113対では`A1`・`A2`のtoken indexが対内で一致しないことが分かった（役割文の長さが対内で異なるため。prefixのtoken数が一致しない対は4対）。位置のずれ自体がラベルの手がかりになりうるため、研究実施者の判断で位置ベースラインを追加した。取得・解析の前の変更である。
- **同位置ロジット（`G`のみ）：** `G`での次トークン対数確率について、「送金先の最初の数字 − 参照口座の最初の数字」を
  スコアとして使い、同じ`paired_accuracy`を計算する。モデル自身の出力がどこまで説明するかの上限として示す。
  `S`では次トークンが両口座で共通（`GB`）なので、同位置ロジットのベースラインは存在しない。

## 5. Probe・層・fold

手順1の設定をそのまま使い、結果を見て選び直さない。

- **Probe：** `logistic`（L2、C=1.0、`max_iter`=1000、seed=20261027）と`paired_dom`。標準化はfold内の学習側のみで行う。
- **層：** 残差は全36層を保存する。判定に使う層は次のとおりである。
  - `A1`・`A2`・`T`：0、8、16、24、32（手順1と同じ）。
  - `S`・`G`：8、16、24。RDRの「スロット付近は中間層に限定する」に従う。最終層付近は同位置ロジットと構造的に相関するため使わない。
  - 層35、および上記以外の層は報告のみとする。報告用に計算する層は、各位置とも0・8・16・24・32・35
    （判定層を含む）とする。それ以外の保存層は、この出力IDでは解析しない（2026-11-12明確化）。
  - `D`は全層とも報告のみである。
- **判定セル：** `A1`・`A2`・`T`がそれぞれ5層×2 probe、`S`・`G`がそれぞれ3層×2 probe。合計42セル。
- **Fold：** 主はファミリー単位の除外（6 fold）。系列単位の除外（40 fold）を比較用に報告する。同じ対は必ず同じ側に置く。

## 6. 指標

手順1と同じとする：`paired_accuracy`（主）、プールAUROC、層別値（ファミリー、U / D、規則、境界）、
40系列単位のbootstrap区間（2,000回）。

**帰無分布：** 系列単位のラベル反転を100回行う。各反復で**42セル全体の最大値**を取り、family-wiseのp値とする（最小値は1/101）。
位置ごとではなく全体で補正する。位置間の比較が本仕様の目的であり、どの位置かを後から選ぶ自由度も補正に含めるためである。

## 7. 位置ごとの判定

各位置について、その位置の判定セルに手順1のR1〜R4を適用する（閾値も同じ。p値は6節の全体補正値を使う）。

- **R4：** その位置の陽性対照AUROCが、判定する全層で0.95未満。
- **R1：** あるセルで次をすべて満たす：`paired_accuracy` ≥ 0.80、family-wise p < 0.05、全表層ベースラインより0.10以上高い、
  6ファミリー中5以上で0.5超、U / Dの両方で0.5超。
- **R2：** family-wise p < 0.05だが、R1を満たさない。
- **R3：** family-wise p ≥ 0.05。

追加の記述（判定は変えない）：

- 特異性対照のAUROCが、主ラベルのU層AUROC − 0.05以上なら、「順序情報一般の読み出し」の可能性を併記する（手順1と同じ）。
- `G`では、probeの`paired_accuracy`と同位置ロジットの値を並べる。ロジットの値以上であれば、
  「モデルの出力で説明できる範囲」と併記する。

## 8. 仮説への対応づけ（解釈の規則）

位置ごとの判定から、次のように記述する。いずれも「近い」「整合する」までとし、仮説の採用や棄却とは書かない。

位置を3つの段階にまとめる：**口座段階**（`A1`・`A2`）→ **生成前段階**（`T`）→ **書き出し段階**（`S`・`G`）。
段階の判定は、その段階のどれかの位置がR1ならR1とする。R1がなく、どれかがR2ならR2、それ以外はR3とする。

規則は上から順に適用する（2026-11-12、研究実施者が確定。当初の表には、第1行と例外の例が両立しない矛盾があったため改めた）。

| 順 | 条件 | 記述 |
|---|---|---|
| 0 | 判定する5位置のどれかがR4 | 仮説への対応づけを保留し、原因を調べる。位置ごとの判定値は報告する |
| 1 | すべての位置がR3 | 線形には検出されなかった。H1〜H3のどれも支持しない |
| 2 | 最初にR1となる段階より後に、R3の段階がある | 信号が途中で消えるパターンとして記述し、仮説への対応づけはしない |
| 3 | 最初にR1となる段階が口座段階 | H1に整合（口座を読んだ時点ですでに読める） |
| 4 | 最初にR1となる段階が生成前段階 | H2に整合 |
| 5 | 最初にR1となる段階が書き出し段階 | H3に整合。R1が`G`だけなら、同位置ロジットとの比較を併記する |
| 6 | どの段階もR1でない（R2を含む） | パターンをそのまま記述し、仮説への対応づけはしない |

例：`A2`でR1、`T`でR3なら、規則2により対応づけはしない。

注意：

- `T`は手順1と**同じデータ・同じ位置**の再測定であり、手順1の再現（独立な確認）ではない。
  手順1と値が異なる場合は、その差を数値誤差として報告する（9節の事前確認2）。
- 早い位置で読めることは、選択がその時点で決まったことを示さない。後の位置で上書きされている可能性がある。
- `A1`では、口座より後に書かれた役割文を見られない（3節）。`A1`で読めない結果は、H1の否定とは書かない。

## 9. 事前確認（取得の前に行い、結果をログに記録する）

1. **トークン化：** 240条件すべてで、正準prefixと書き出し・`GB`・数字を連結してトークン化したとき、
   保存済みのprefixのtoken列が変わらないこと。`S`・`G`の位置のtokenが全条件で同一であること。
   対内の2口座で、`G`の次の数字tokenが異なること。どちらの口座も提示テキストにちょうど1回現れること。
   どれかを満たさない条件があれば、その条件を除外せず停止する。
2. **`T`の一致：** 先に2条件を取得し、`T`の残差が正準bundleの保存値と一致するかを確認する。
   系列長の違いによる数値差があれば、その最大相対差を記録する。差が出ても停止はせず、ログに記録する。
3. **書き出しの妥当性：** 実走行112件の`send_money`呼び出しが、この書き出しで始まるか（`recipient`が最初の引数か）を、
   生成テキストだけを見て確認する。外れる割合をログに記録する（停止条件にはしない）。
4. **資源：** GPUメモリの最大値が12 GiB以下であること。

## 10. 取得の実行

- 実装とテストをコミットし、クリーンなcommitで新しいruntime freezeを作る（既存のfreezeは上書きしない）。
- 1条件1 bundleの不変なraw run bundleとして保存する：`artifacts/runs/argrec672-v1-ps-001-cNNN`。
  保存内容は次のとおり。
  - 6位置×36層の残差（bfloat16）
  - 各位置のtoken index・token ID・offset
  - `S`・`G`・`D`での候補口座の数字tokenの対数確率と、上位20 token
  - 入力token列のchecksum、正準bundleのmanifest checksum
  - commit、freeze、モデル・トークナイザーの版
- 技術的失敗は、新しい不変bundleとして保持してから停止する。再試行は新しいrun IDで行う。
- 容量の見込み：1条件あたり約1.8 MB、240条件で約0.43 GB。

## 11. 解析の実行と出力

- 取得とは別のcommit・別のコマンドで解析する。
  不変な派生出力`artifacts/processed/argrec672-v1-dg-006-position-sweep/`に保存し、`results/`に小さい要約、`docs/experiment_logs/`に記録を置く。
- 解析は一度とする。後から位置・層・ラベルを追加した場合は別の出力IDとし、探索的と明記する。

## 12. 必要なテスト

- 位置の決定：提示順による`A1`・`A2`の決定、offsetとtokenの対応、書き出しの連結でprefixが変わらないこと、`D`の構成。
- リーク防止：検証行を読み込まないこと。位置がラベルを使わずに提示順だけで決まること（対内で`A1`・`A2`が指す口座の文字列が一致すること。token indexは一致しなくてよい）。
- 同位置ロジット：対数確率差の符号と、`paired_accuracy`の既知値。
- family-wise補正：42セル全体の最大値で計算していること。
- 合成データ：特定の位置にだけ信号を埋め込むと、その位置だけがR1になること。
- 再現性：同じseedで同じ出力になること。出力先が既にあれば失敗すること。

## 13. この仕様に含めないこと

- 手順4（探索的パッチング）。位置と層の候補は本仕様の結果から選ぶが、その選び方と介入の手順は別の仕様で決める。
- 攻撃条件。手順2で残った比較軸の決定は、攻撃実験の設計時に行う。
