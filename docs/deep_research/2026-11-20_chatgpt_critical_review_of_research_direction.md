## **総合評価**

**結論：現在の第1部は、内部表現に対する介入実験として一定の結果を得ていますが、「送金先の決定時点を因果的に特定した研究」としては成立していません。第2部も、Claudeの提案をそのまま実施すると、既存研究の追試に近い結果か、解釈できない介入結果に終わる危険があります。**

**確信度：高**

私が最も問題視するのは、研究の問いと測定している現象の間にあるずれです。

- **研究の問い：** モデルはいつ、どの口座を使うと決めるのか。
- **現在測定しているもの：** ある時点・層の残差ストリームを別条件の値で置換すると、次の口座トークンの選好がどれだけ変わるのか。

この二つは同じではありません。

モデルがすでに決めていた送金先を、出力直前の内部状態の改変によって上書きできたとしても、それは「その時点で初めて送金先が決まった」ことを示しません。

また、関連研究の一次資料を確認したところ、CounterSteer はすでに、引数操作型攻撃について、生成前には線形に読み出しにくい一方、引数値の出力時には強く読み出せることを報告しています。したがって、**「Gで決まる」という観察単独を国際会議向けの主要な新規性にするのは難しい**と判断します。

## **1. 第1部の結果で最も危ない点**

**結論：最大の問題はG層24への依存そのものではなく、TとGの介入結果を同じ意味で比較できる保証がないことです。次いで、全残差置換が何を移したのか識別できない問題が重大です。**

**確信度：高**

### **1-1. G層24の1セルへの依存**

査読者は次のように指摘するでしょう。

> 層24を中間層に含めたという人為的な基準だけで、H3を支持するかどうかが変わる。これはモデルの内部機構についての発見ではなく、判定規則の産物ではないか。

実験結果を分解すると、重要なのは「層24がP-STRONGになった」という分類ではなく、次の連続的な変化です。

G位置のパッチング効果

116対。正規化効果の平均。学習データ上の探索的解析。

00.250.50.75104812162024283235

層20から層24の間で急激に効果が増えています。ただし、測定点は4層間隔なので、実際にどの処理で変化したかは不明です。

さらに重要なのは、これは層が深くなるほど、出力ロジットを直接支配する計算に近づくという構造上の効果かもしれないことです。

**最小限の追加分析**

1. 層の閾値を使用せず、NEの連続値と信頼区間を主結果として提示する。
2. 保存済みデータで、ファミリー別、方向別、パッチング後の選好反転率を集計する。
3. 計算資源があれば層21〜27を追加測定する。ただし、結果閲覧後に選んだ層なので探索的とする。

**判断：H3の判定は履歴として保存し、卒論の主張からは外すべきです。**

「G位置の層24以降で、候補口座に対する選好が大きく移動した」と書くほうが、測定結果に忠実です。

### **1-2. cross > matched**

これは、現在の研究で最も解決する価値のある未解明点の一つです。

査読者の質問は次のようになるでしょう。

> 異なる文脈からのactivationのほうが、対応する文脈からのactivationより強い。移したのは抽象的な選択ポインタではなく、口座の文字列を出力するための情報ではないか。

現在の`cross`条件は、別ファミリーではありますが、口座のidentity、提示順、正解方向が一致しています。

そのため、以下を分離できません。

- どちらの役割を選ぶかという抽象的な情報
- 特定の口座文字列を出力する情報
- 提示順に依存した情報

さらにNEは元の正常差で正規化しているため、0.879という値だけから「抽象化された表現の転移が強い」とは言えません。crossのファミリーCでは平均1.323であり、異なるdonorの出力選好の強さや正規化の影響も疑う必要があります。

**最小限の追加分析・実験**

まず、保存済みの各ペアについて、NEだけでなく次の量を比較します。

\\[ \Delta m = m\_{\mathrm{patched}}-m\_{\mathrm{original}} \\]

ここで \\(m\\) は候補口座間の系列対数確率差です。ドナーの正常margin、受け手の正常margin、パッチ後marginを同時に比較してください。

次に、新規介入を行うなら、donorの次の要素を独立に変えます。

| donorの条件      | 目的               |
| ------------- | ---------------- |
| 同じ口座・逆の役割     | 現在のmatched       |
| 同じ口座・逆の役割・別文脈 | 現在のcross         |
| 異なる口座・同じ役割関係  | identityへの依存を調べる |
| 同じ口座・提示順を反転   | 提示順への依存を調べる      |

各比較では、役割、提示順、口座identityをどれだけ固定したかを明示し、donorの口座が受け手にない場合は、その口座への確率質量も観測します。

代表的な24〜48条件程度でよいと考えます。新しい全240条件に対するフルスイープより、こちらのほうが研究上の価値は高いです。

ただし、現在のcross結果が大きいこと自体を機構の証拠にしてはいけません。これは**何が転移したのか未識別であるという結果**です。

### **1-3. Gが出力直前である問題**

これは国際会議で最も強く批判されると予想します。

重要なのは、GとTでは介入の下流にある計算が非対称なことです。

現在の介入が持つ構造的な非対称性

特にリポジトリの[パッチング解析ログ](https://github.com/Fumiel/whose-goal-is-it-anyway/blob/main/docs/experiment_logs/2026-11-16_activation_patching_analysis.md?utm_source=chatgpt.com)には、T・Sの最終層を置換した効果がゼロになる構造上の理由がすでに記されています。

これは深刻です。

T位置の層35を変更しても、後続トークンの処理にその変化を伝達する経路がありません。一方、G位置の層35は次トークンの予測へ直接作用します。

したがって、**Tの全層で効果がほぼゼロ、Gの深い層で効果がほぼ1という観察には、選択の時点とは無関係の説明が存在します。**

また、Gで測定しているのは自由生成されたツール呼出しだけではありません。固定した`send_money`の書き出しをモデルに与えて、候補口座の系列対数確率を教師強制で計算しています。

そのため「モデルが自然にその行動を選んだ」とも言えません。

**最小限の追加実験**

優先度順に以下を求めます。

1. 自由生成された実際のツール呼出しについて、G位置での選好と実際に選ばれた口座の一致率を求める。Gに到達しなかった実行も分母として報告する。
2. Gでの線形probeと、同じG位置の次トークンlogit差、口座全体の系列対数確率差を比較する。内部probeがlogit以上の情報を持つか検証する。
3. G以外の固定位置・非対象引数位置を陰性対照として置換する。さらに、Tについては単一残差ではなく、後続位置へ情報を伝達する複数位置またはKV経路への介入を小規模に試す。

3は実装負担が高いので、卒論では1と2を優先します。ただし、単なる別位置への同規模の置換でも位置間の伝達経路は揃いません。その限界は残ります。

**この実験が証明したのは、Gの状態への介入で出力選好を変更できることです。決定時点を特定したわけではありません。**

### **1-4. int8量子化**

**結論：int8は、それだけで研究を無効にする欠点ではありません。ただし、層20から24での急変を、非量子化モデルでも存在する機構として説明するには不足しています。確信度：高。**

問題は、量子化によって演算結果や表現の幾何が変わりうることです。特に今回のように層間の急変を解釈する場合、その可能性を無視できません。

リポジトリには、int8環境でトークンを追加するだけでも、以前の位置の値が変わる場合があると記録されています。計算経路を統一したのは適切ですが、これによって量子化の影響自体が消えるわけではありません。

最小限の検査として、12〜24対程度で異なる量子化方式による感度分析を行います。可能であれば非量子化BF16との比較が望ましいものの、8Bモデルを16GB VRAMへそのまま載せるのは困難なので、CPUオフロードや追加計算資源が必要です。4-bitでの再現は代替的な頑健性検査であり、BF16での再現と同等ではありません。

量子化方式が変わっても効果が残れば限定的な頑健性を主張できます。再現しなければ、Qwen3-8Bのint8実装固有の観察として報告すべきです。

### **1-5. 追加で指摘したい統計的・実験的問題**

**確信度：高**

一つ目は、120対が独立な120標本ではないことです。40系列が6ファミリーに属しているため、系列単位bootstrapでは、ファミリー間の不確実性を十分に捉えられない可能性があります。ファミリー単位のleave-one-out分析と、6ファミリーを再標本化する感度分析を併記すべきです。

二つ目は、失敗した4対を除外した結果が116対になっていることです。除外規則は事前固定されていますが、正常条件で選好方向が逆になった対を外した結果であるため、「正常選択が成立した条件での介入効果」という条件付きの推定です。全120対での生margin変化と、意図した方向への反転率も必要です。

三つ目は、P-DISRUPTがゼロであっても、破壊的な介入がゼロではないことです。G層24ではmatchedの10/232、crossの9/232に個別の破壊フラグがあり、Tの浅い層では11〜16%程度あります。中央値によるセル判定と、個別の異常な介入は区別してください。

四つ目は、**検証側のデータを「完全に未閲覧」とは呼べない可能性**です。[位置スイープ仕様](https://github.com/Fumiel/whose-goal-is-it-anyway/blob/main/docs/phase2_position_sweep_spec.md?utm_source=chatgpt.com)には、G/H・I/J系列が以前の開発段階ですでに閲覧されたことが記されています。現在のパッチングで使用していないことと、研究プロセス全体で未閲覧であることは異なります。

第1部に対する最終的な査読判断は、**計算手順は再現可能な形で管理されているが、構成概念の妥当性と因果解釈が主要な弱点**、です。

**確信度：高**

### **差別化すべき軸**

私が選ぶなら、**「引数identityの表現」と「そのidentityを実際のツール引数に採用する過程」の分離**です。

仮説を次のように変更します。

> モデルは候補口座の内容を表現できていても、その内容が最終的な送金先に採用されるとは限らない。間接プロンプトインジェクションは、候補値そのものよりも、その選択への因果的寄与を変える可能性がある。

この仮説を検証するなら、単に口座を読めるかでは不十分です。

必要なのは、口座identity・提示順・出所・役割を独立に操作し、**どの変化が出力選好を引き起こすか**を検証することです。

たとえば、同じ2口座を与えた状態で、参照元の信頼性だけを変更します。口座の文字列情報を保ったまま選好だけが変わり、対応する内部表現への介入でも同様の変化が再現できるなら、現在より強い証拠になります。

ただし、これも自動的に「権限を表す方向が見つかった」ことにはなりません。内容、出所、役割に対応する特徴量を区別し、その方向への介入が出力を選択的に変えることが必要です。

**新規性として狙うべき順序は次の通りです。**

1. IPIによって、どの引数値が採用されるかが変わる。
2. その変化を、表層文言や単純な値のコピーと区別できる。
3. 分離した内部成分への介入が、引数選択を選択的に変える。
4. 未知の系列・攻撃でも再現する。

このうち1と2までなら卒論の有力な成果です。3と4まで進められれば、国際会議向けの研究として検討する価値が高くなります。

なお、CounterSteerは引数出力時に読める信号を、すでに生じた判断の反映として解釈しています。したがって、現時点で「Gで初めて決まる」と反対の解釈を主張するには、既存研究より強い証拠が必要です。

## **3. 第2部の実験設計に欠陥はないか**

**結論：現行案には、攻撃条件の定義、攻撃なしとの対応関係、モニタの正当性という3つの欠陥があります。特に、IPIの成功と、単なる文書内の口座選択の変化を区別する実験が不足しています。**

**確信度：高**

### **3-1. 攻撃者口座は第3候補にするべきか**

私なら、**第3の口座を主条件、既存の参照口座を副条件**にします。

| 条件       | 利点                       | 主な問題                           |
| -------- | ------------------------ | ------------------------------ |
| 既存の参照口座  | 第1部との比較が容易。pilotの失敗様式に近い | 通常の役割混同とIPIを区別しづらい             |
| 第3の攻撃者口座 | 攻撃者由来の値が採用されたことを識別しやすい   | 候補数、口座の露出、tokenizationの違いが交絡する |

既存の参照口座を攻撃者口座にすると、もともとモデルが取り違えやすかった口座を選んだだけなのか、攻撃文の指示に従ったのか判別しにくくなります。

実際、今回の誤受取人14件中13件は、もう一方の口座との取り違えです。これはIPIがなくても発生する失敗様式です。

一方、第3候補を使う場合には、**攻撃なし条件にも第3候補の口座を中立的な情報として登場させる**ことを推奨します。

そうしないと、攻撃あり条件だけに新しい口座の文字列が追加されるため、口座identityへの露出の有無と、悪意ある指示の効果を区別できません。

なお、3候補への変更は、現在の2候補用のNE指標をそのまま使えることを意味しません。出力候補、評価指標、破壊判定を新たに定義する必要があります。

### **3-2. 攻撃あり／なしの対応条件**

少なくとも、次の3条件を同一タスクの中で比較することを求めます。

C0

**Clean：攻撃指示なし**

信頼された依頼には送金先Aが指定され、外部書類にはA・B・Cの口座情報が含まれる。外部書類に指示の上書きは存在しない。

C1

**Placebo：無害な追記**

同じ外部書類に、口座Cについての補足説明などを追加する。ただし、送金先を変更する指示は含めない。

C2

**IPI：送金先変更の指示**

C1と同じ位置に、口座Cへの送金を指示する攻撃文を配置する。正規の送金先Aは変わらない。

三条件で固定するものは、正規ユーザー要求、正規の受取人、口座文字列、提示順、金額、ツールの種類、ツール結果の取得経路です。

変えるものは、信頼できない外部情報中に含まれる指示の有無と内容です。

ただし、C1とC2で文字列長まで完全に一致させることは必須ではありません。極端な長さの違いを避け、token数、注入位置、書式を記録して、交絡の可能性を分析してください。

さらに、**「振込先が変更されました」という記述がなぜ悪意ある指示なのか**を定義する必要があります。

たとえば、ユーザーが「書類に記載された最新の振込先を使用して」と依頼しているなら、変更通知への追従が必ずしも攻撃成功とは限りません。

正規依頼によって送金先Aが明示的に指定され、外部書類にはそれを上書きする権限がない、という権限関係を固定すべきです。

### **3-3. 攻撃成功率が低すぎる・高すぎる場合**

次のように研究目的を分けて判断します。

| 攻撃成功率の状況 | 可能な分析               | 不可能・困難な分析        |
| -------- | ------------------- | ---------------- |
| ほぼ0%     | 攻撃への耐性や失敗要因の記述      | 成功した乗っ取りの機構解析    |
| 20〜80%程度 | 成功・失敗の比較、内部表現と行動の関連 | それだけで因果機構を同定すること |
| ほぼ100%   | 攻撃有無による介入効果の比較      | 成否を予測する検出器の評価    |

20〜80%は、今回の探索的な実験を進めるための目安であり、理論的な最適値ではありません。

攻撃が成功しない場合、成功例だけを探して攻撃文を何度も改良すること自体は開発データであれば可能です。しかし、選んだ攻撃を新しい未閲覧データで評価しない限り、その成功率は選択バイアスを含みます。

また、**攻撃成否だけで条件を選んでパッチングすると、成功例特有の内部状態を事後的に選んだことになります。**

主解析では、攻撃成功・失敗にかかわらず事前指定した対象を評価し、成功例の分析は副次的に行うべきです。

### **3-4. 攻撃あり／なしのパッチング**

Claude案の「攻撃あり／なしの状態をGで入れ替える」は、そのままでは弱いです。

攻撃あり条件で口座Cを出力し、攻撃なし条件でAを出力する場合、Gの全残差を置換して選好が移っても、単に口座Cを出力する状態が移っただけかもしれません。

この問題を避けるには、少なくとも次の2つを区別します。

**実験A：攻撃による選好の変化**

\\[ \Delta\_{\mathrm{IPI}} = m\_{\mathrm{attack}} - m\_{\mathrm{control}} \\]

ここで \\(m\\) は、攻撃者口座と正規口座の対数確率差です。

この実験は、攻撃文によって候補選好がどれだけ変化したかを調べます。

**実験B：攻撃に伴う内部状態の因果的寄与**

攻撃あり条件と無害な対照条件の間で状態を置換し、選好が移るか調べます。

ただし、全残差置換ならば、あくまでも「攻撃によって変化した状態のどれかが選好に影響する」という結果です。

「攻撃者の指示を権限あるものと扱う表現」を示したいなら、より限定した方向または成分への介入が必要です。

したがって、12月の段階ではAを必須、Bを限定的な追加実験にすることを推奨します。

### **3-5. G位置モニタの設計**

**結論：現状の第2部(3)は、防御の新規性を主張する段階にありません。単純な出力logitとの差別化と、正規の送金を妨げないことの検証が必要です。確信度：高。**

第一の問題は、G位置の読み出し自体です。

現在の候補口座はすべて`GB`で始まり、その直後の数字で分岐します。この構造なら、Gからの次トークン確率を比較するだけで候補を識別できる可能性があります。

その場合、学習したprobeにどれだけ追加価値があるのでしょうか。

必須の比較対象は以下です。

- G位置の次トークンlogit差
- 候補口座全体の系列対数確率差
- 文字列・口座identity・位置などを用いた表層ベースライン
- 信頼された元の依頼と、実際のツール引数を比較する通常の引数検証器

特に最後の比較は重要です。

正規の受取人口座が外部の信頼できる情報から取得できるなら、モデルの内部状態を監視するよりも、実際の送金前に引数を照合するほうが簡単で確実な可能性があります。

逆に正規の受取人が分からないなら、Gの表現を読むだけでは、その口座が正当かどうか判断できません。

第二の問題は、**オンラインモニタとして評価していない**ことです。

現在のG位置は、固定した書き出しを与える教師強制条件です。実際のエージェントでは、呼出し形式が変化したり、別のツールを呼んだり、`recipient`が最初の引数でなかったりする可能性があります。

さらに、口座先頭の1トークンだけで判定するなら、同じ先頭数字を持つ複数の口座で識別不能になるかもしれません。

最低限、先頭数字が一致する候補を用意し、この問題を検査すべきです。

### **モニタの評価指標**

防御を主張するなら、私は次を必須とします。

| 指標                  | 何を評価するか             |
| ------------------- | ------------------- |
| TPR @ FPR 5%        | 正常な呼出しの誤停止を制限した検出性能 |
| Clean Task Success  | 防御によって正常タスクを壊さないか   |
| Attack Success Rate | 実際の攻撃成功を抑えたか        |
| Monitoring coverage | 対象とする呼出しをどれだけ監視できたか |
| Latency / overhead  | 実行時間・追加推論量の増加       |
| 出所照合ベースラインとの差       | 内部モニタを用いる意味があるか     |

FPRは正常な送金だけでなく、正当な変更通知が存在する場合にも測定すべきです。

たとえば正常な送金100件で誤停止が0件でも、95%信頼区間の上限は概ね3.7%です。50件程度では、低いFPRを十分な精度で示すのは困難です。

さらに、モニタの閾値は開発データで固定し、未閲覧の評価データで一度だけ測定します。

**適応型攻撃については、実際にモニタの判定結果を攻撃者へフィードバックし、攻撃文を更新する実験が必要です。** 単に未知の攻撃文で評価することは、適応型攻撃の検証ではありません。

そこまで行えないなら「適応型攻撃への頑健性は未検証」と明記すべきです。

第一に、**H1・H2・H3を、互いに排他的な決定時点の仮説として扱わないこと**です。モデルは早い段階から候補を表現し、後続の計算で選好を更新し、出力時に具体的な文字列を確定させることがありえます。「一つの決定時点」を前提にした競合仮説は、この可能性を適切に表現できていません。

第二に、**全残差を置換する介入と、特定の情報や機構を操作する介入を区別すること**です。現在の実験は前者です。国際会議を目指すなら、単なる出力変化から、どの情報成分が選択に寄与したかという主張へ進む必要があります。

第三に、**研究計画書の確認的主解析を整理すること**です。リポジトリの[research_proposal.md](https://github.com/Fumiel/whose-goal-is-it-anyway/blob/main/docs/research_proposal.md?utm_source=chatgpt.com)と[experimental_protocol.md](https://github.com/Fumiel/whose-goal-is-it-anyway/blob/main/docs/experimental_protocol.md?utm_source=chatgpt.com)には、`argument_readout`、`authority_score`、両者の交互作用による確認的回帰が残っています。今回の実験へ軌道修正したのであれば、その主解析を維持するのか、正式に置き換えるのかをRDRで決定しなければなりません。

これは単なる文書整備ではなく、結果を見た後に研究仮説を変更したことを正確に扱うために必要です。

### **現段階で卒論に書ける最も強い結論**

> Qwen3-8Bのint8実行環境における正常な送金先選択課題では、候補口座位置での高精度な読み出しは局所的な文言から説明できた。一方、口座出力直前の内部状態に対する活性化置換は、層24以降で候補選好を大きく変化させた。ただし、この結果だけでは引数選択の決定時点や、転移した表現の内容は特定できない。

ここまでは、現在の証拠に即した結果として成立します。

しかし、これはまだ「間接プロンプトインジェクションがどのように引数を乗っ取るか」という問いへの答えではありません。

**12月に必要なのは、大量の新しいactivationではなく、攻撃が正常な引数選択を変えることを厳密に示し、その変化の原因について少なくとも一つの競合説明を排除する実験です。**
