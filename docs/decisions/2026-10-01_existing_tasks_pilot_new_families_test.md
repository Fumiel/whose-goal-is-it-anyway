# 既存Banking系列を予備実験、新系列を開発・確認的評価へ配分する

## 判断と変更範囲

2026-10-01、研究実施者が「既存タスクで予備実験を行って方針を固め、確認的評価には
新しいタスク系列も設計して独立clusterを確保する」方針を採用した。
既存の8系列候補を予備実験用と確認用に無理に分割せず、既存系列は予備実験へ積極的に使う。
すべての既存系列を均等に実行することや、既存だけで30clusterを満たすことは要求しない。

`supersedes`はRDR-2026-09-22-01第6節の「Phase 1以降の全splitから系列を除外する」
規則の部分改訂を表す。shakedownで使ったtask・attack系列と近い変種も、**新しいrunとして
探索的予備実験に再利用できる**。この許可だけで、それらをprobe training / validationに
移すことは認めない。旧記録のその他の規則、正式選定標本の除外、shakedownの行動結果を
モデル選定やgate閾値へ使わない規則、過去のshakedown runを研究データへ転用しない規則は維持する。
凍結済み選定設定とchecksumは当時の記録として保存する。

モデル選定で使った系列も、新しいrunで予備実験に再利用できる。shakedown・選定・予備実験・
条件調整に使った系列と近い変種は確認的testへ入れない。新系列も、共通attack goal/style等で
既使用系列とつながれば、第8節の関係graphに従ってtestから除外する。

## 系列の配分

| 用途 | 配分方針 | 実行前の要件 |
|---|---|---|
| 予備実験の中心 | 既存のパスワード、請求書、返金、家賃、住所系列 | 条件と停止・移行規則を固定し、新しいrun IDで実行する。測定が明確な条件から広げる |
| 予備実験の対照 | 既存の履歴照会・要約、不足指定・委任条件 | 正規変更callのある主比較と、副次対照を区別する |
| 保留・要監査 | 既存の5/6、11 | RDR-2026-10-01-01の評価器保留・recipient監査を維持する |
| 新系列の開発側 | 新規task・attack系列の一部をtraining / validationへ | モデル挙動を見て条件・probe・測定方法を調整する系列はこちらへ置く |
| 確認的test | 開発側・既使用側と関係graphで分離した新系列 | Phase 3で方法とsplitを凍結し、その後にモデル評価する。結果で条件を選び直さない |

## 新系列の設計と検証

予備実験と並行して新系列の設計案、評価器、task・attack関係graphを作る。
予備実験開始前には配分方針と設計の進め方を記録し、実際の新系列数・最高位group数と
最終splitはPhase 3で凍結する。30groupの実現を予備実験開始時点で達成済みとは扱わない。

名前、金額、口座、表現だけの変更は新系列として数えない。正規目的、引数決定規則、参照資料、
必要な操作の組合せの意味的な違いと、attack goal/style/templateの重複を審査する。
新task ID数と最高位の独立group数は別々に報告する。

新タスクは別namespace・versionと来歴を持ち、native Bankingタスクと区別する。
初期状態、tool schema、正規・攻撃call、注入位置、user-task / attackの成功述語、無操作・
正規・攻撃状態の対照検証を定義する。新規タスクのAgentDojo互換性は実装・検証するまで主張しない。
単一Bankingドメイン・単一モデルの範囲を維持し、別ドメインへの移行は別RDRで扱う。

設計候補のmodel-free検証を行い、確定した候補を連結成分単位で開発側と確認側へ分ける。
確認側へ割り当てた後の事前確認はschema・checksum等の第8節の許容範囲に限る。
モデルの成功・攻撃成否・margin等を見て修正した系列は開発側に置き、同じ系列を後から
「未使用test」に戻さない。最終test結果を見て系列を追加・交換しない。

## 理由と影響

既存Bankingタスクは測定経路と実現可能性を調べる足場になる一方、近縁タスク、既使用系列、
評価器問題があるため、既存8系列だけを研究全体の上限とする配分では未知系列評価が難しい。
探索段階では既知の失敗を調べることに意味があり、shakedown系列の新規実行まで隔離する
旧規則はその目的に対して過度に保守的だった。過去runと最終testを隔離する原則を保ちながら、
探索的予備実験での系列再利用を許す。

Research Question、仮説、主解析、決定論的比較、暫定450–700実行・確認的30cluster目標、
group分割規則を維持する。変更はタスクの調達・配分とshakedown系列のpilot再利用である。
新系列設計の工数は予備実験と並行して見積もり、目標を満たせなければtest開封前の別RDRで
規模・範囲を見直す。期限延長やcluster目標の引下げは今回決定しない。

判断はモデル選定結果とソース監査を確認した後、新しい探索的予備実験の前に行った。
新しいモデルrun、task・attack実装、split manifestはこの文書更新では作成していない。
確認的testは未作成・未実行・結果未閲覧である。
