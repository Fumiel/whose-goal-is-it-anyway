# D1M・D2資料構造の修正と、2026-10-26系RDRの現行有効範囲の整理

## 判断

### 1. D1M・D2の資料構造の修正（本文草案の修正）

研究実施者のレビュー指摘（2026-10-26）を採用し、RDR-2026-10-26-06の本文草案を修正した。指摘は、D1Mでは「口座があるのは対象項目だけで、他は支払済み」、D2では「別の支払先が口座登録なし」のため、モデルが指定IDや支払先名を照合せずに唯一の口座を選べる、というものである。

- **D1M**: 全項目をopenとし、各項目に固有の口座行を置く。対象項目の口座は候補口座（`v1`～`v4`）、他項目の口座は候補ではない架空IBAN（`other_entry_account_values`、mod-97検査済み）とする。口座行は対象項目と同じ文型で、項目IDに対応させる。対象項目の位置は系列ごとに入れ替え、常に末尾にならない。
- **D2**: 登録簿の別の支払先にも固有の口座（候補ではない架空IBAN）を載せ、「no account on file」は使わない。請求書の支払先名を登録簿と照合しないと口座を選べない。登録簿内の対象行の位置も入れ替える。
- **UN・UIの資料**: 対象行が常に先頭だった点を同様に位置入替えとした。
- 検証コードは、D1M項目の全open・全項目の口座行、D2登録簿の全支払先の口座、他項目口座がユーザー指示やD1M・D2以外の資料に出ないこと、`rx`/`ry`が候補口座以外で同一であることを拒否規則に加えた。
- 付随修正: 候補ペアの割当を規則と相関しないよう変更した（3タスク周期との同期を解消）。バッチ・検証での候補均衡は維持される。

非候補口座はラベル`argument_present`に影響しない。ただし、**対象でない項目の口座が資料に現れる**ため、資料由来の正例は「その位置までに、指定項目の口座として提示された候補」という意味に限り、口座の出現そのものとは区別する。これで「成功＝照合できた」と読める度合いは上がるが、モデルが実際に照合したことは実走行・attention・介入では確認しておらず、課題設計の根拠にとどまる。位置の入替えは完全な均衡ではなく（例: D1Mの対象位置は先頭11・中間7・末尾6）、規則別の候補数もやや偏る。

### 2. 2026-10-26系RDRの矛盾の整理

同日に連続して出した6件のRDRは、`supersedes`の範囲が部分的で、本文草案の作成時点では次の食い違いがあった。過去のRDRは書き換えず、本RDRで**現行有効な読み方**を定める。

| 食い違い | 現行有効な扱い |
| --- | --- |
| RDR-01の25学習＋10検証系列×各5タスク＝500＋200条件、100条件刻み | RDR-06が学習40＋検証16系列×3タスク＝480＋192条件、8系列・96条件刻みへ改めた。RDR-01のAUROC 0.80基準、主指標の既定、段階的fit、validation配分の前fix要件は維持 |
| RDR-04が採用した10系列候補とCodex 700条件草案の35系列・各5タスク | RDR-05が題材ファミリー単位へ置き換え済み。10系列候補は個別の採用としては残さず、ファミリー候補（A～J）の素材としてのみ参照する。Codex草案は変更しない参考資料 |
| RDR-05が「672条件配分・金額計算廃止・Uシリーズ内の規則交差・文型数は未採用」 | RDR-06が配分・金額明記・U0/UN/UI・D1/D1M/D2・文型16＋8を採用。RDR-05のファミリー分離、REC/DON学習側算入、別系統LLM監査は維持。`role_swap_auc`主指標、段階0、取得二系統、日程・停止規則は未採用のまま |
| RDR-02の5規則（D1＝一資料の口座、D2＝二資料の照合）に複数項目から項目IDで選ぶ資料規則がない | D1Mを、RDR-02の「一資料の受取口座」の変種として追加する（資料由来、露出は`first_tool_to_assistant`）。RDR-02の4条件・露出後ラベルは維持 |
| RDR-02の「対象IDと口座の対応」「5タスクの変動」 | UIは指示内対応として維持。5タスクの変動は3タスクへ置換（RDR-06） |
| RDR-02とRDR-03がともにRDR-04の`supersedes`の対象として並ぶ | RDR-02の条件・規則はRDR-03・04で部分改訂されたが、本整理により、規則・4条件・露出後ラベルはRDR-02、文型多様化はRDR-03、混合曲線はRDR-04（一部RDR-05・06）を参照する |
| v1草案の表でF3がD、バッチ表でU | F3はUシリーズ（RDR-06） |
| 本文草案文書がD1Mを「他項目settled」と記述 | 上記1で修正。文書も更新 |

各RDRの`status`は変更しない（過去の記録を書き換えない）。現行の適用順は、RDR-01（基準・段階化）→02（規則・4条件）→03（文型）→04（混合曲線）→05（ファミリー・監査）→06（構造・規模）→07（本RDR）である。

## 適用時点と限界

この判断は旧96条件の結果閲覧後、確認的test未作成・未閲覧、新規収集前の開発上の設計修正である。主指標、取得位置・方式、関係graph、split、native evaluator、LLM監査仕様、runtimeは未凍結であり、本RDRはそれらを決めない。修正した草案はモデル・native tool・tokenizerで未検証であり、研究実施者の再レビュー前である。旧96条件の宣言・run・audit・probe結果は変更しない。
