# Recipient内容probeの系列拡張と段階的学習曲線

## 判断と適用範囲

2026-10-26、研究実施者は、最初の96条件で学習内と未知系列の性能に大きな差があったことを受け、Bankingの`send_money.recipient`内容probe用に新しい開発コレクションを段階的に設計・収集する方針を決めた。計画規模は学習用25意味系列×各5タスク×各4対応条件＝500条件、開発用validation 10意味系列×各5タスク×各4対応条件＝200条件である。学習用は5系列・100条件ずつ増やし、100、200、300、400、500条件で学習曲線を評価する。全タスク本文の完成を最初のfitの前提にはしない。

研究実施者が指定した「十分なprobe性能」の数値基準は、学習に使っていない意味系列に対するAUROC **0.80以上**とする。初回96条件との比較可能性のため、実行仕様で別の主指標を採用しない限り、候補口座の文字列が当該位置までに出現した条件での候補別recipient対別用途AUROCを四候補で等重み平均した値を、この基準の主指標とする。これはAUROC点推定値の開発上の到達基準であり、各候補・各系列が0.80以上であること、信頼区間下限が0.80以上であること、語彙baseline超過、IPI条件への妥当性、目的採用または因果性を意味しない。候補集合や主指標を変更する場合は最初の新規fit前に理由と評価方法を別仕様へ固定する。

この判断は規模、段階化、数値基準の**計画決定**であり、35系列の具体的な独立性、175タスクの本文、4条件の全cell、口座値、検証集合の反復使用・留保配分、層・位置・正則化、停止規則、split manifest、実行runtimeを凍結しない。各新規runの前にはRDR-2026-10-14-01と実験プロトコルの実行前要件を満たす個別仕様が必要である。旧96条件の宣言・split・run・audit・派生probeは変更しない。既存64学習条件を新規500条件の学習曲線へ算入するかは未決定とし、最初の新規fit前に固定する。旧REC/DONの32条件は既に性能を見た開発資料であり、新しい未使用validationとして数えない。

## 観測済みの根拠、時点と代替案

[初回probe fit](../experiment_logs/2026-10-26_argument_recipient_96_probe_fit.md)では、学習64条件の4096次元残差に線形probeをfitし、未知のREC/DON各16条件での最良の四候補平均AUROCは0.484、TF-IDFは0.852だった。[学習内診断](../experiment_logs/2026-10-26_argument_recipient_96_train_diagnostic.md)では全18層・正則化設定で四候補ともAUROC 1.000だった。[学習系列除外診断](../experiment_logs/2026-10-26_argument_recipient_96_train_series_cv.md)も系列ごとの大きなばらつきを示した。これらは過学習、意味系列・文型の分布差、取得位置、表現そのものの弱さを切り分けない。64条件が16タスク・4系列であり、保守的な関係graph上は一つの学習側連結成分であることも、表面的な条件数だけでは汎化を評価できない理由である。

この判断はpilot、二文書v2、96条件のモデル結果、およびREC/DON validation結果を閲覧した**後**の開発変更である。確認的testは未作成・未実行・未閲覧であり、今回使う系列も後から確認的testへ戻さない。2026-10-25の未知系列で語彙baselineを安定して上回らない場合の主張縮小基準は達成済み扱いにしない。現在のprobeを主解析用に採用せず、「目的表現」の強い主張を留保したまま、追加の開発実験で可能性を調べる。

採用しなかった案は、学習内AUROC 1.000を妥当性の根拠にすること、単なる口座・金額・近い言い換えの増殖を独立系列として数えること、旧REC/DONを未使用検証へ戻すこと、700条件をすべて収集してから初めてfitすること、AUROC 0.80の単独達成でIPI readoutを承認することである。

## 段階的設計・検証の条件

- 100条件の各段階は、5意味系列×各5タスク×各4条件の**完全な系列単位**で追加する。各バッチのrecipient決定規則、文型、口座役割・位置、候補別正負数を可能な範囲で均衡させる。先のprobe誤りを見て後続タスクを変更した場合は、その時点・変更内容・影響を記録し、単純な標本数効果の学習曲線と区別する。
- 同じタスクの4条件、近い言い換え、共通の具体的な目的・形式、および既使用系列との関係をgraphで監査する。25/10という系列名の件数を独立連結成分数とはみなさない。学習とvalidationをつなぐedgeがあれば、そのまま未知系列AUROCに算入しない。
- 段階間では同じラベル定義、候補値、取得境界・位置、前処理、学習器、評価対象と主指標を比較可能な形で保つ。変更が必要なら新しい解析仕様・曲線versionを作る。標準化・次元削減・較正は各段階の学習データのみでfitする。
- validationの繰り返し閲覧による選択バイアスを抑えるため、10系列のうち反復モニタリングに使う系列と最終選択後まで留保する系列の割当、層・正則化の選択、0.80到達時の停止・確認規則を**最初の新規fit前**に固定する。全10系列を毎段階閲覧する場合は、得られる最大値と到達時点を適応的な開発結果として扱い、未使用validationでの確認と混同しない。具体的な配分は本RDRでは決定しない。
- AUROC 0.80に加え、候補別・系列別値、語彙baseline、ランダムラベル対照、較正、欠測、独立成分単位の不確実性を報告する。単一の点推定値による到達はPhase 2終了条件や主解析用probe採用の十分条件ではない。tool出力IPI、引用・禁止、両recipient候補の対応対照はRDR-2026-10-22-03に従い別途検証する。
- 条件本文・ラベル・graph・split・評価器・監査規則・取得位置・資源上限・runtime freezeを新規実行前に固定する。未完のバッチを完了扱いにせず、技術失敗と行動失敗を区別し、raw/processed bundleを上書きしない。

## 研究計画・プロトコルへの影響と残る判断

新しい500＋200条件だけで、[研究計画第8節](../research_proposal.md)のprobe教師・対照200～300実行という暫定配分と全体約450～700実行の暫定枠に達するか超える。これらの数値を本拡張コレクションの上限としては適用しない部分改訂とする。確認的IPI最低30クラスター、単一モデル・単一ドメイン、同一tool・異なる主要argumentの主張範囲、決定論的比較、test隔離は変更しない。開発拡張が確認的収集の時間・保存容量を圧迫するため、実行可能な総配分と停止規則を新規run前に見積もる。

影響を受けるのはRQ1の`argument_readout`妥当性確認と、RQ2/3でそのscoreを使えるかという前提である。仮説や主回帰式はこの判断で変更しない。新しい条件・runは旧96条件と別versionにし、生成仕様、系列関係、split、各段階の学習入力・検証入力、選択履歴、checksumを残す。主モデル・主ドメインの正式採用、最終probe仕様、確認的test開始の判断は別途行う。
