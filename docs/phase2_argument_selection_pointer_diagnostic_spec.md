# 選択ポインタ診断の仕様

**状態：** 判定基準は2026-11-06に研究実施者が確定。同日、訓練側の既存キャプチャで実行しR1。[実験ログ](experiment_logs/2026-11-06_argument_selection_pointer_diagnostic.md)を参照。\
**関連：** [RDR-2026-11-06-01](decisions/2026-11-06_argument_selection_timing_course_correction.md)、[設定](../configs/analysis/phase2_argument_selection_pointer_diagnostic_v1.json)、[実装](../src/goal_takeover/phase2/argument_recipient_672_selection_pointer.py)\
**位置づけ：** 結果閲覧後に追加する、訓練データのみの探索的診断。確認的解析でも、独立検証でもない。

## 1. 目的

既存のprobeは口座別のidentityラベルで学習した。この診断では、口座に依存しないラベルで次を確かめる。

> `Tend_assistant`の残差から、2つの口座のうちどちらを使うかを、口座identityに依存せず線形に読めるか。

これはRDRの仮説H2を、提示順という符号化に限って検査するものである。

## 2. データ

- 対象は`argrec672-v1-003`の訓練側正準キャプチャ、`Tend_assistant`位置である。
- 新規の実行、GPU、モデル読み込みは不要である。
- 検証条件（G/H/I/J）は読み込まず、`validation_rows_loaded: 0`を出力に記録する。
- 実走行の結果とモデルの生成callはラベルに使わない。

## 3. ラベル

### 主ラベル`recipient_first`

二口座の役割入替え条件（`rx_ref_y`、`ry_ref_x`）について、提示テキスト内で受取人口座が参照口座より前にあれば1、後にあれば0とする。提示テキストは、`source_role`がuserならユーザー指示、toolなら資料本文を読取順に連結したものである。

### 宣言からの確認結果（2026-11-06、モデル不使用、訓練側のみ）

| 確認項目 | 結果 |
|---|---|
| 対象 | 240条件、120対 |
| ラベル1 / 0 | 120 / 120 |
| 規則・ファミリー・バッチ別 | すべて1 / 0が同数 |
| 2口座の出現回数 | 240条件すべてで各1回 |
| tool由来90条件のユーザー指示 | どちらの口座も含まない |
| 対内のラベル | 120対すべてで反転 |
| 先に提示される口座 | 120対すべてで対内同一 |
| 受取人別のラベル1 / 0 | v1は38 / 22、v2は26 / 34、v3は30 / 30、v4は26 / 34 |

対内では、口座の文字列と提示位置が揃い、役割を表す文の順序だけが変わる。受取人の口座別配分は均衡していないため、identityベースラインで確認する。

### 解釈の限界

ラベルは条件から決まり、行動から作らない。ただし、読めたとしても、それは役割文の談話順序を保持しているだけかもしれない。**読めることは選択を示さない。** 読めないことも、非線形な符号化や提示順以外のポインタを排除しない。

## 4. 対照

| 対照 | 定義 | 目的 |
|---|---|---|
| 陽性対照 | `source_role`（user / tool）。訓練側480条件 | 手順が明らかな情報を読めるか確認する。履歴構造で自明に決まる情報なので、研究上の証拠にはしない |
| 特異性対照 | Uタスクの`account_block_position`（`before_task` / `after_task`）。対内で同じ値のため、`logistic`のプールAUROCで主ラベルのU層と比較する | 選択に無関係な順序情報も同程度に読めるかを見る |
| ランダムラベル | 系列単位でラベルを反転し、同じ手順を反復 | グループ構造を保った帰無分布を作る |
| TF-IDF | 正準prefix全文の文字2〜5-gram + 主ラベル用ロジスティック回帰、同じfold | 表層情報の上限を見る |
| 長さ | prefixのtoken数のみ | Kale & Vishwanathが指摘した長さ手がかりを見る |
| 口座identity | 受取人口座のone-hot | 表の配分の偏りで説明できる分を見る |

## 5. Probe

設定は固定し、結果を見て選び直さない。

| Probe | 仕様 |
|---|---|
| `logistic` | fold内学習データのみで標準化。L2、C=1.0、`max_iter`=1000、seed=20261027 |
| `paired_dom` | fold内学習データのみで標準化。各対の差分（ラベル1 − ラベル0）を平均した方向を使う。fitする閾値はない |

- **層：** 0、8、16、24、32、35。層35は最終層の構造的相関があるため（計画書第7節）、報告のみで判定に使わない。判定に使うのは5層×2 probeの10セルである。
- **Fold：** 主は**ファミリー単位の除外**（A〜Fの6 fold）。比較用に系列単位の除外（40 fold）も報告する。同じ対は必ず同じ側に置く。

## 6. 指標

- **主指標`paired_accuracy`：** 除外foldの各対で、ラベル1の条件のスコアがラベル0の条件より高い割合（同点は0.5）。対内で比べるため、foldごとのスコア尺度の差と課題間の差の影響を受けにくい。
- **副指標：** プールしたAUROC。
- **層別：** ファミリー、U / D、規則（U0/UN/UI/D1/D1M/D2）、境界。
- **信頼区間：** 40系列を単位とするbootstrap（2,000回、seed固定）。系列は6ファミリーに入れ子であり、ファミリー数が少ないためファミリー単位の区間は作らず、ファミリー別の値を併記する。
- **帰無分布：** 系列単位のラベル反転100回。各反復で10セルの最大値を取り、family-wiseのp値を計算する（最小値は1/101）。

## 7. 判定基準（2026-11-06確定）

全基準をファミリー除外の結果に適用する。

| 分類 | 条件 | 次の扱い |
|---|---|---|
| **R4 手順の問題** | 陽性対照のAUROCが判定対象の全層で0.95未満 | 解釈せず停止し、原因を調べる |
| **R1 H2候補** | ある1セルで次をすべて満たす：`paired_accuracy` ≥ 0.80、family-wise p < 0.05、全表層ベースラインより0.10以上高い、6ファミリー中5以上で0.5超、U / Dの両方で0.5超 | 別RDRで未閲覧の系列での評価を計画する。この結果だけで選択を主張しない |
| **R2 弱い信号** | family-wise p < 0.05だがR1を満たさない | 探索的結果として記録し、位置スイープへ進む |
| **R3 非検出** | family-wise p ≥ 0.05 | 線形な提示順ポインタは検出されなかったと記録し、H1 / H3を中心に位置スイープへ進む。H2全体の棄却とは書かない |

R1でも、同じ層の特異性対照AUROCが主ラベルのU層AUROC − 0.05以上なら、順序情報一般の読み出しの可能性を併記する。判定は上の順に、R4から確認する。

0.80は既存の到達基準を踏襲するが、もとは`role_swap_auc`に対する値であり、対内正解率への転用として記録する。

## 9. 実装方針

既存の`argument_recipient_672_train_readout.py`の次を再利用する：`train_rows_and_run_ids`、`load_canonical_features`、`clean_commit`、`publish`。

必要なテスト：

- ラベル導出：3節の表をすべて再現する。対の反転を確認する。
- リーク防止：検証行を読み込まない。同じ対や系列がfoldをまたがない。標準化を学習側だけで行う。
- 指標：`paired_accuracy`の既知値、同点、対の欠損時のエラー。
- 再現性：同じseedで同じ出力。既存の出力先があれば失敗する。
- 合成データ：既知の提示順方向を埋め込むと検出でき、無信号では0.5付近になる。
